# Plan 01-01: Backend Dwell Setting & Security Hardening

## Objective
Harden backend gate verification by transitioning the minimum dwell window from a hardcoded 10-minute constant to a dynamic `AppSetting` (default 5 minutes), recording early-attempt audit logs upon premature return scans, and updating verification test suites.

<context>
- Decisions: `D-05` (configurable dwell setting), `D-06` (dwell countdown DENY), `D-07` (early-attempt audit logging), `D-08` (guard shift logging).
- Related files:
  - `apps/api/src/gate/gate.service.ts`
  - `apps/api/prisma/seed.ts`
  - `apps/api/test/gate.e2e-spec.ts`
  - `verify-gate-return-flow.cjs`
</context>

| Client -> Gate API | Guard handheld scanner submits signed token or pass code |
| Gate API -> Database | Atomic status update and immutable audit log append |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-01 | Tampering | GateService.scan | high | mitigate | Verify ECDSA P-256 signature against registered student public key within skew window |
| T-01-02 | Repudiation | GateService.recordEvent | medium | mitigate | Atomic database transaction recording GateEvent and AuditLog with guard ID and server timestamp |
| T-01-03 | Elevation of Privilege | GateService | high | mitigate | Enforce JwtAuthGuard and Guard role permissions on scan endpoints |
| T-01-SC | Tampering | Package Dependencies | high | mitigate | Package lockfile integrity and strict version pinning |
